Longhorn v2 Data Engine 使用实践

Longhorn 除了提供传统的 v1 Data Engine 外，还支持基于 SPDK（Storage Performance Development Kit）的 v2 Data Engine。v2 Data Engine 已在 Longhorn v1.12.0 版本中正式 GA（General Availability）。

v1 与 v2 Data Engine 的主要区别如下：

对比项 Data Engine v1 Data Engine v2
数据路径 在 Instance Manager 中运行各 Volume 的 Engine 和 Replica 进程，通常通过 iSCSI 向主机提供块设备 基于 SPDK，Replica 存储在原始块设备上的逻辑卷中，常规 blockdev 前端通过 NVMe / TCP 向主机提供块设备
节点磁盘 使用 filesystem 类型的磁盘，需要先格式化为 ext4/XFS 文件系统并挂载 使用 block 类型的磁盘，由 Longhorn 直接管理未格式化的原始块设备，优先推荐本地 NVMe
节点资源 主要根据工作负载和 Replica 数量规划资源 额外需要为 SPDK 分配内存和专用 CPU，默认预留 2 GiB HugePages
快照删除 删除 volume-head 的直接父快照后，可能先将其标记为移除，随后通过 Purge 操作清理 支持在线合并，删除操作完成后快照即被移除
功能差异 支持 strict-local 数据本地性 不支持 strict-local，但支持 v1 不具备的快速 Volume 克隆和 QoS
RWO / RWX RWO 使用块设备，普通 RWX 通过 Share Manager 提供 NFS 服务 同样支持 RWO 和普通 RWX，RWX 仍然依赖 NFS Client

v1 与 v2 Data Engine 性能对比

RWO Volume 性能测试

为了对比 v1 和 v2 Data Engine 在 RWO 场景下的性能，采用以下测试方法：

  • 分别使用 longhorn-v1-ssd 和 longhorn-v2-ssd 创建容量及 Replica 数量相同的专用测试 PVC，容量均为 10 GiB。
  • 选择容量、型号及负载一致的 v1 文件系统磁盘和 v2 原始块设备。
  • 将两个 PVC 挂载到同一个包含 fio 的测试 Workload 中，依次执行性能测试。

RWX Volume 性能测试

创建 PVC 和 Workload：

同时在三个 Pod 中执行性能测试，并将测试结果输出为独立文件：

根据 Share Manager 与 fio Pod 所在节点的位置关系，分别测试以下四种场景：

  • v1 的 Share Manager 位于本机，v2 的 Share Manager 位于远端。
  • v1 的 Share Manager 位于远端，v2 的 Share Manager 位于本机。
  • v1 和 v2 的 Share Manager 均位于远端。
  • v1 和 v2 的 Share Manager 均位于本机。

每个场景执行四轮测试，并交替调整 v1 和 v2 的测试顺序：

  • 第一轮和第三轮：先测试 v1，再测试 v2。
  • 第二轮和第四轮：先测试 v2，再测试 v1。

说明：

本机表示 fio Pod 与对应的 Share Manager 运行在同一个节点上，远端则表示两者运行在不同节点上。

表格中的总 IOPS 为对应 fio Pod 四轮测试结果的平均值。

后两轮差异指只取第三、四轮的结果：先算 v1 在这两轮的平均 IOPS，再算 v2 的平均 IOPS，最后用 (v2 平均值 ÷ v1 平均值 − 1) 得到百分比。每一轮都包含一次 v1 和一次 v2 测试。

场景一：v1 本机，v2 远端

v1 读 IOPS v1 写 IOPS v1 总 IOPS v2 读 IOPS v2 写 IOPS v2 总 IOPS 四轮差异 后两轮差异
288.0 122.7 410.7 284.5 121.1 405.6 −1.3% −0.2%

测试结论

  • RWO Volume： v2 Data Engine 的性能优势较为明显。在测试中，v2 的 IOPS 和带宽均高于 v1，同时平均延迟和 P99 延迟也更低。
  • RWX Volume： v2 Data Engine 整体上也具有一定的性能优势，但测试结果受到 Share Manager 所在节点位置的显著影响。

测试仅供参考，具体性能表现需要视环境情况而定。
